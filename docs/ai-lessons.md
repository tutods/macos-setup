# AI Lessons: one-off gotchas

Specific incidents worth remembering but too narrow for standing rules. Each entry: what happened → what to do instead. Sources are commits in this repo unless noted.

## Claude Code setup

- **A skill repo is not automatically a plugin marketplace**: only repos with `.claude-plugin/marketplace.json` can be installed as plugins. 12 of 30 sources had none when this repo moved off `npx skills` and had to be dropped; see `docs/dropped-skill-sources.md`.
- **Plugins are coarser than skills**: a marketplace's plugin usually ships several skills, and the plugin name rarely matches the skill name. Read the repo's `marketplace.json` and match the plugin whose `source` dir holds the `skills/<name>/` you want; guessing produces a config that silently installs nothing useful.
- **`enabledPlugins` used to merge live + nix, so a removed plugin stayed enabled unless it was also added to a hand-maintained `purgedPlugins` tombstone list.** That list only grew and nothing signalled when an entry was safe to drop. Now `settings.nix` merges via `aiLib.mergeJsonObject`: Nix is authoritative for every key it declares, so dropping a plugin from `home.ai.plugins` is enough on its own. Foreign top-level keys are left alone, but a foreign hook event survives only if it is in `keepHookEvents`, and `permissions.allow` is declared so a deploy clears click-granted rules. A plugin added through the Claude Code UI is still disabled on the next `./nix.sh` (never add plugins via the UI).
- **Custom skills are copied, not symlinked.** A `home.file` symlink points into the read-only Nix store, and Claude Code has historically treated a skill dir as writable, which a 0444 symlink broke. Nothing writes there now, but the copy is kept: `customSkillsReconcile` needs real dirs to reconcile. `lib/ai.nix:mkLocalSkills` does `cp -R` + `chmod -R u+w`, ordered after `linkGeneration` so Home Manager's teardown of the old generation doesn't delete the fresh copy, and before `customSkillsReconcile` so every copy lands before the sweep.
- **`autoCompactWindow` only takes an absolute token count, there is no percentage syntax and no `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` env var, both were invented, silently ignored, and left a 60%-compaction assumption that never fired.** A fixed count sized for 200k also fires far too early on `opusplan`, since it executes on Sonnet 5, which runs a native 1M-token window on the API, and a count sized for 1M fires far too late on any 200k session. Left unset entirely: Claude Code compacts at each session's own model-tuned default instead of a hand-picked number.
- **MCP config merges, it never replaces.** `~/.claude.json` is live session state Claude Code writes to constantly, so the deploy merges into `mcpServers`. Nix is authoritative for additions only, removing a server needs `claude mcp remove <name> --scope user` once by hand. Deploy with no other session running, or a concurrent write can be lost.
- **A plugin's bundled `.mcp.json` registers MCP servers too**: so `claude mcp list` shows servers this repo never declared. Drop the plugin to remove them; declaring a competing copy just duplicates the tool schemas in every session.
- **A tool that depends on the model remembering to invoke it does not get used.** `rtk` was installed, given its own Nix module, documented in eight files, and made the sole content of `~/.claude/CLAUDE.md`. It was invoked zero times, because nothing enforced the prefix. Removed. Same failure the repo already fixed by moving `~/.claude/context/` into skills. Before adding a tool that needs the agent to opt in every time, decide what enforces it, or expect it to sit idle. The original fix proposal, a `PreToolUse` rewriter, was rejected then: silently mutating a command means the output you reason over is not the output the command produced. **Revisited and enabled**: today's hook (`rtk-rewrite.sh`, a wrapper around `rtk hook claude` declared in `settings.nix` as its own matcher group) preserves error strings, test failures, and diffs verbatim and strips only boilerplate, so the fidelity objection no longer applies; it never auto-allows (a `permissionDecision` is emitted only when an explicit allow rule matched the original command, and this repo's allow list is Nix-owned and read-only-command only), and deny rules are honored with top precedence. The zero-invocation lesson stands: enforcement is the hook, not the model's memory.
- **Don't duplicate a server the plugins already provide.** A hand-rolled `github` MCP server sat unused next to `github@claude-plugins-official`, and a `filesystem` server duplicated Claude Code's native Read/Glob/Grep, both only added tool schemas to every session.
- **opencode's built-in permission default is `{"*":"allow", doom_loop:"ask", ...}`, so an MCP tool with no rule of its own is allowed — the "no rule means ask" premise was wrong.** `config.nix` carried an `mcpToolAllows` binding written on that premise; it was also never referenced, so it changed nothing either way and is now deleted. Confirmed empirically: 319 completed MCP tool calls, zero rows in the `permission` table, and `evaluated permission=playwright_browser_navigate pattern=* action.permission=* action.action=allow` in the log. Consequence: a project opting into an MCP server via a project-root `opencode.json` needs no allow rule, and a server's *schema size* is the only reason to think twice about adding one. `doom_loop:"ask"` is the built-in loop guard, which is why the runaway sessions below ran as long as they did (nobody was there to answer the ask).
- **An MCP server's tool schema is paid on every request, so a server's value is (tokens saved by its tools) minus (schema tokens × request count).** `code-review-graph` ships 30 tools (~9.7k tokens of schema) and this machine had called exactly four of them across 27k messages. `serve --tools a,b,c,d` trims the exposed set to ~1.7k tokens, an ~8k saving per request with no lost capability; `verify-opencode.sh` asserts the flag is present because a dropped `--tools` is invisible at runtime. Check actual tool-call counts (`opencode.db`, `part.data`'s `tool` field) before deciding a server is worth its schema. The same trim now applies on the Claude side (`mcp.nix`), where the server's 30 tools had **zero** lifetime calls in every recorded transcript.
- **`external_directory` asks are the opencode friction tax, and /tmp needs both spellings.** 208 recorded asks; 122 were reads under `/tmp` (agents verifying work in scratch dirs) and the rest opencode's own config/data dirs. macOS symlinks `/tmp` -> `/private/tmp` and the glob match is on literal path text, so an allow for `/tmp/*` alone leaves `/private/tmp/*` prompting — both spellings are in the allow list now. `git diff` asks, by contrast, were fully historical: they predate the `bashRules` deploy and zero have occurred since, so read-only git forms are pinned to allow as belt-and-braces, not as a live fix.
- **The `npx skills` tree's declared sources can be pure dead weight.** All five declared sources (vercel-labs/agent-skills, biomejs/biome, mindrally/skills, vercel/turborepo, remotion-dev/skills — 23 skills, ~1.2k tokens every request) recorded zero loads; only Orca-sourced skills (preserved via `opencodeSkillsExternalSources`) were ever used. The source list is now empty and the reconcile prunes the orphans on deploy. A source earns a slot in `home.ai.opencodeSkillsSources` only with recorded loads behind it.
- **A tool's own installer can scatter files for AI assistants this machine never runs.** `code-review-graph install` (aliased `init`) is described by its own `--help` as "Register MCP server with AI coding platforms", and its `uninstall` says it removes "data, configs, hooks, and generated skills"; `rtk init` takes `--gemini` and `--agent claude|cursor|windsurf|cline|kilocode|antigravity|kimi`. This machine runs Claude Code and opencode only, so neither installer is ever run: `code-review-graph` is installed via `pipx install` and wired into the MCP config by hand, and rtk's hook scripts (`rtk-rewrite.sh`, and now `crg-autobuild.sh`'s call into the `code-review-graph` binary) are hand-written instead of generated. `code-review-graph build`/`update` stay safe to run unattended (the new `SessionStart` autobuild hook, see [ai-setup.md](ai-setup.md)): they only write the repo's own `.code-review-graph/` directory, and the tool writes its own `.gitignore` containing `*` inside it, so no repo-level gitignore entry is needed. Before wiring any CLI's own "install"/"init" subcommand into a hook or activation script, read its help text for what else it touches.
- **Ponytail's `SubagentStart` hook re-injects about 5 KB of persona text on every subagent dispatch, with no matcher**: kept for now as a known cost, since it's the only thing carrying the persona into a subagent's isolated context.
- **`npx skills add`-style installs land outside Nix**: real directories under `~/.agents/skills/` and `name -> ../../.agents/skills/name` symlinks under `~/.claude/skills/`, loaded every session and invisible to `verify-plugins.sh`. `customSkillsReconcile` removes the symlink half on deploy; `~/.agents/skills/` itself is pruned by hand.
- **Both r/ClaudeAI threads on token burn are unfetchable from Claude Code**: reddit.com, old.reddit.com, the `.json` endpoint, r.jina.ai, web.archive.org, archive.ph and redlib mirrors all refuse it. Paste the text when a Reddit thread matters.

## Nix / dotfiles

- **Repo scripts (`nix.sh` etc.) are zero-dependency bash**: no `gum`, no external TUI helpers; a bootstrap script can't assume its own dependencies exist yet (gum TUI experiment was reverted on request).
- **Git remotes stay SSH**: don't "fix" them to HTTPS during audits; SSH is the intended auth path.
- **Open-by-default posture, not full-auto**: every opencode agent allows `edit`/`webfetch`/`websearch` and `bash` falls through to an allow-all catch-all, but `bashRules` in `config.nix` now layers a destructive-command ask/deny set (`dangerAsk`/`dangerDeny`) on top of the secret denies, see [opencode-setup.md](opencode-setup.md). The delegation boundary is still convention only, stated in the generated `AGENTS.md`, not a permission the harness holds it to.
- **A list-shaped permission value passes `nix flake check` but makes opencode reject the whole config file at startup.** `permission.external_directory` was set to a list of path globs; opencode's schema wants a `PermissionRuleConfig`, meaning the string `"ask"`/`"allow"`/`"deny"` or an object mapping a glob to one of those, never a bare list. The list produced "Configuration is invalid at ~/.config/opencode/opencode.json ... Expected PermissionRuleConfig, got [...]" plus "Things to fix!" on every launch, and the repo's own build-time assertion missed it because it only checked permission key names, not value shape. Fixed by making it an object (`"*"` asks, the Obsidian/`.dotfiles`/Developer trees allow) and extending the assertion in `config.nix` to check value shape as well as key names, so a list can't ship here again. A schema that accepts a string or an object needs its own value-shape check; a key-name check alone lets the wrong shape through.

- **`mas` in an activation script must run as the target user, not root.** The App Store session and the Spotlight index mas reads are per-user, so a root-run `mas list` returns nothing and every `mas install` fails, reporting all declared apps (installed ones included) as failed. Running it by hand as the user works fine, which hides the cause. `install-mas-apps.sh` now drops to the user via `sudo --user <user> --set-home` (mirroring nix-darwin's own brew-bundle invocation) and lets mas elevate itself. Separate trap in the same script: mas 7 right-aligns 9-digit IDs in `mas list` with a leading space, so a `^id ` line-start matcher never sees them; match space-delimited anywhere on the line instead.

- **Overriding `nix-homebrew`'s `brew-src` input pins a version nix-homebrew's wrapper may not match.** The module copies upstream `bin/brew`'s exported-var list verbatim into its generated wrapper, while the library keeps the overridden version's startup contract. Renovate bumped `nix-homebrew` from `09a921d` (wrapper tail from brew 6.0.22, which exports `HOMEBREW_ORIGINAL_BREW_FILE`) to `c11cccf` (tail from brew 7.0.4, which dropped the export), but the repo still pinned `brew-src` at 6.0.13, whose `Library/Homebrew/startup/config.rb` does `ENV.fetch("HOMEBREW_ORIGINAL_BREW_FILE")` — every `brew` call after that deploy died with a `KeyError` before any command ran. The override must track the ref in nix-homebrew's **own** `flake.lock` (`nodes.brew-src.original.ref`), not stay at a hand-picked version; when Renovate bumps nix-homebrew, check that ref before deploying. Interim unblock while broken: `HOMEBREW_ORIGINAL_BREW_FILE=/opt/homebrew/bin/brew brew …`. Note `brew --version` exits in bash before loading Ruby, so it works even when everything else is broken — test with `brew list` instead.
