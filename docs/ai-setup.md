# AI Setup

Everything Claude Code reads under `~/.claude/` is generated by this flake. Hand-editing `~/.claude/settings.json` or `~/.claude/rules/workflow.md` is overwritten on the next deploy; change the Nix source instead. opencode (personal machine) shares the same instruction sources, see [opencode-setup.md](opencode-setup.md).

## What is loaded every session

The fixed context every session carries before the first prompt: the rules file, every enabled plugin's skill descriptions, the SessionStart text plugins inject unconditionally, the in-repo local skill descriptions, the in-repo agent descriptions, and every connected MCP server's tool names.

Snapshot measured 2026-09-22 on the work machine, not a live guarantee, re-measure to check the current cost. Before this rebuild: ≈21k tokens total, rules file 4.2k, plugin skill descriptions 10.2k, plugin SessionStart injections (caveman, ponytail, superpowers) 3.1k, local skill descriptions 2.6k, agent descriptions 1.0k, MCP tool names 0.9k. After: ≈7-9k. Of that, the caveman and ponytail SessionStart injections (≈2.3k) are a deliberate keep, not overhead to chase, and ≈0.9k is claude.ai account connector tool names, which only claude.ai's own settings can remove, not this repo.

Standing rule: anything stack- or project-specific belongs in that project's own `CLAUDE.md`/`.claude/`, never here. Every local skill, agent and instruction in this repo is machine-wide by construction and loads in every session regardless of what the session is about, so the bar for adding one here is that it holds on every repo on the machine.

## Instructions

`instructions/delegation.md` (Claude only, capped at 1 KB) states the subagent-first override and the per-turn caps. `instructions/shared.md` (harness-agnostic, kept short because opencode folds it into its byte-budgeted `AGENTS.md` (`verify-opencode.sh`, see [opencode-setup.md](opencode-setup.md)), also read by opencode's `AGENTS.md`) carries tooling, git, vault, code, destructive-ops, security, writing, evidence-and-scope, decisions, learned rules and model tiers. A role's `home/roles/<role>/ai/instructions.md` is appended last via `home.ai.extraInstructions`. On the personal machine the same shared sources also generate `~/.codex/AGENTS.md` (`home/roles/personal/ai/codex.nix`, a Codex-specific `codex.md` delta plus `shared.md` plus the role instructions, no `delegation.md`). `home/common/ai/instructions/default.nix` concatenates the three into `~/.claude/rules/workflow.md`, loaded in every session. `~/.claude/CLAUDE.md` is rtk's own file, an `@RTK.md` import, not generated by this repo.

## Settings

`home/common/ai/settings.nix` merges its keys into `~/.claude/settings.json` on every deploy via `aiLib.mergeJsonObject`. `model` and `modelSettings` are app-written preferences, set with `/model`, and must never be declared here or added to `dropKeys`: `mergeJsonObject` keeps any undeclared live key, so declaring `model` would fight the in-app picker on every deploy. A declared top-level key replaces the live value; `permissions` and `hooks` merge one level deeper; a live hook event survives only if its name is in `keepHookEvents` (Orca's events); `dropKeys` clears `autoCompactWindow`, the one case where leaving an undeclared live key alone would silently override a value this module documents as intentionally unset. `autoMemoryEnabled = false` is declared and re-applied on every deploy: the Obsidian vault is the only store for session-learned facts, read on demand by `vault-search`, and rules that must hold without a lookup live in `instructions/shared.md` "Learned rules". `enabledPlugins` is rewritten wholesale from `home.ai.plugins` on every deploy, so dropping a plugin there disables it and adding one through the Claude Code UI does not survive the next deploy.

Env vars:

| Var | Purpose |
|---|---|
| `CLAUDE_VAULT_FOLDERS` | role-scoped vault folders the `vault-lint` agent checks scope coverage against |
| `CLAUDE_CODE_SUBAGENT_MODEL` | default subagent model (`sonnet`) when neither a per-call `model` nor an agent's own `model:` says otherwise |
| `CLAUDE_CODE_GOAL_CHECKIN_MINUTES` | set to 0, so a goal waiting on background tasks never triggers a full-context check-in turn (background work already notifies on completion) |
| `PONYTAIL_SUBAGENT_MATCHER` | narrows ponytail's SubagentStart injection to the agent types that actually write code |
| `CLAUDE_RECON_LIMIT` | distinct inline Read/Grep/Glob targets allowed per main-thread turn before `delegate-nudge.sh` denies a further one |

### Hooks

| Event | Matcher | Script |
|---|---|---|
| PreToolUse | Bash | `block-ai-attribution.sh` |
| PreToolUse | Bash | `destructive-guard.sh` |
| PreToolUse | Bash | `rtk hook claude` (rtk binary, no script) |
| PreToolUse | Read\|Grep\|Glob | `delegate-nudge.sh` |
| PreToolUse | Edit\|Write | `force-delegation.sh` |
| PreToolUse | Agent | `subagent-model-gate.sh` |
| PostToolUse | Edit\|Write | `biome-fix.sh` |

Two of these are hard gates sharing turn-boundary logic in `lib/turn-key.sh` (a non-empty `agent_id` bails out so subagents are never restricted, `prompt_id` is the turn key, counters live in a per-namespace dir with a 2-hour GC), so the two hooks never define "a turn" differently:

- `force-delegation.sh` denies a main-thread Edit/Write past 4 distinct files in a turn; repeat edits to an already-allowed file stay free.
- `delegate-nudge.sh` denies a further distinct inline Read/Grep/Glob target past `CLAUDE_RECON_LIMIT` (default 8); re-reading an already-counted target stays free.

`subagent-model-gate.sh` denies any Agent dispatch that omits `model`, names anything other than `haiku`, `sonnet` or `opus` (or the matching `claude-*` id), or uses `subagent_type: fork`, which always inherits the parent model. The deny text carries the tier table, so the main thread picks a tier by complexity on the retry; `CLAUDE_CODE_SUBAGENT_MODEL` stays as the fallback for agents whose frontmatter pins nothing.

`block-ai-attribution.sh` rejects AI attribution in commits, PRs and reviews. `destructive-guard.sh` turns the irreversible commands `shared.md` names (`git reset --hard`, `git clean`, whole-tree checkout or restore, force push, recursive `rm` outside `/tmp`, `find -delete`, `DROP`/`TRUNCATE`) into a permission prompt, so auto mode still stops for a human yes. The `rtk hook claude` hook calls the rtk binary directly to rewrite read-only commands for token-cheap output. `biome-fix.sh` runs `biome check --write` on just the edited file, a no-op unless the project has a biome config.

## Plugins

Marketplaces and plugins live in `home/common/ai/plugins.nix`: `caveman`, `mattpocock-skills`, `ponytail`, plus the built-in `code-review`, the fixed set on both machines. Third-party marketplaces are pinned to a reviewed commit sha (`@<sha>`); a pin after the last `@` that is not a full 40-char lowercase commit sha fails `nix flake check` outright. `scripts/verify-plugins.sh` is the one check that catches a typo'd plugin name, since a bad name otherwise fails silently: Claude Code installs nothing and logs nothing.

Stack- or project-specific plugins are enabled per project instead of here: `frontend-slides` in the `frontend` repo's own `.claude/settings.json`, and Mindera's `mp-ai-workbench`/`mp-fe-design` (the `ai-workbench` marketplace) in the `frontend`, `workspace` and `ai-workbench` repos' own settings, since project settings take precedence over user settings and a worktree shares the main checkout's file. A project's `enabledPlugins` can also set a global plugin to `false`, turning it off for that project alone; this repo's own `.claude/settings.json` does that for `mattpocock-skills` and carries the permission allow-list for the mandatory checks below.

Personal machine only: a trial of `tokeneconomizer@tokeneconomizer` (`microsoft/TokenEconomizer`, pinned sha) in `home/roles/personal/ai/default.nix`. Its hooks live in the plugin, not `~/.claude/settings.json`. It needs Python 3.10 or newer, and the system `python3` is 3.9, so `home.sessionVariables.TE_PYTHON` points at the Nix `python3`. Because the plugin's own hooks are not in Nix-managed settings, `deploy-doctor.sh` does not see them.

After the first deploy, run these once (pruning defaults to `auto`, which could deny `Agent`, `Workflow` or `Skill` and deadlock the force-delegation hooks; `loopguard` defaults to `nudge`):

```bash
~/.tokeneconomizer/bin/te --host claude doctor
~/.tokeneconomizer/bin/te config set toolprune=propose toolprune_protect=Agent,Workflow,Skill --global
~/.tokeneconomizer/bin/te config set loopguard=off --global
```

Exit: `te toolprune restore` in each repo it pruned, drop the marketplace, plugin and `TE_PYTHON` entries, deploy, `./scripts/claude-cleanup.sh --apply`, then `rm -rf ~/.tokeneconomizer`.

To find which plugin ships a skill:

```bash
git clone --filter=blob:none --no-checkout --depth 1 https://github.com/<owner>/<repo> /tmp/probe
git -C /tmp/probe show HEAD:.claude-plugin/marketplace.json | jq -r '.plugins[] | "\(.name)\t\(.source)"'
git -C /tmp/probe ls-tree -r --name-only HEAD | grep '<skill-you-want>/SKILL.md'
```

A disabled-but-installed plugin costs nothing: only `enabledPlugins` loads at session start. `claude plugin uninstall` is disk hygiene, not required for the token budget.

## Local skills, agents, workflows

Local skills, two agents (`vault-lint`, `vault-search`), one workflow (`llm-council`), declared in `home/common/ai/skills/default.nix`, `agents/default.nix` and `workflows/default.nix`.

`mkLocalSkills` copies, not symlinks, the declared directories into `~/.claude/skills` on every deploy; `customSkillsReconcile` then deletes any directory or symlink there that isn't declared or listed in `home.ai.externallyManagedSkills` (Orca's own `orca-cli`, `orchestration`, `orca-computer-use`, updated by Orca's installer, never this repo, plus Claude Code's own `synced` dir). `mkLocalAgents` and `mkLocalWorkflows` install plain `home.file` symlinks instead: an agent or workflow file is read-only input nothing ever writes into, so a store symlink is safe.

Personal fetched skills (`aiLib.mkFetchedSkills` in `home/roles/personal/ai/default.nix`, each pinned by `rev` and `hash`): `security-audit`, `find-skills` (discovery only, patched with `applyPatches` and an appended `find-skills-adopt.md`), `task-observer` (`disable-model-invocation: true`, its `[ABSOLUTE PATH]` placeholder resolved to `~/.claude`, an appended `task-observer-local.md`, and an `agents/openai.yaml` that blocks implicit Codex invocation), `source-driven-development`, `payload`, `gh-fix-ci`, `gh-address-comments`, the `heygen-com/hyperframes` set (`figma`, `hyperframes`, `hyperframes-cli`, `hyperframes-registry`, `media-use`, `remotion-to-hyperframes`, `slideshow`), `agent-desktop` and `gha-security-review` (getsentry/skills; SkillSpector scores it critical on the attack payloads its references document, and it ships no scripts). Personal local skills (`aiLib.mkLocalSkills` over `home/roles/personal/ai/skills/`): `wp-live-site` and `pt-pt-copy` (European Portuguese copy rules, which unslop's PT-PT block points to). The `agent-desktop` CLI is a Homebrew formula declared in `hosts/darwin/macbook/homebrew/default.nix`. `context7@claude-plugins-official` is in the personal `home.ai.plugins`.

Codex (personal machine only): every skill declared through `mkLocalSkills` or `mkFetchedSkills` is also copied into `~/.agents/skills`, Codex's user skill dir, by `home.activation.codexSkills` in `home/roles/personal/ai/codex.nix`. That dir is shared with Orca and `npx skills` installs, so the sync owns only the names in `~/.agents/.dotfiles-managed-skills`: it deletes owned names that are no longer declared and skips, with a warning, a declared name that exists unowned. A skill that needs a Claude-only tool is excluded with `claudeOnly = [...]` on its `mkLocalSkills` call (`llm-council`, which needs the Workflow tool). A name that already sits in `~/.agents/skills` from an `npx skills` install is skipped until that copy is deleted by hand, and `deploy-doctor.sh` warns about it. `~/.codex/skills` holds Codex's own `.system` and is never written; `~/.codex/config.toml` stays unmanaged.

SkillSpector is packaged on the personal machine: always run `skillspector scan <dir> --no-llm` before adopting a skill or plugin.

Build-time assertions in `lib/ai.nix` fail `nix flake check` when a name in a `names` list has no matching file, or a file on disk under `local/` is missing from its `names` list, the same check that replaced `verify-references.sh`.

## MCP

No MCP server is shared across every machine. The personal role merges `shadcn` into `~/.claude.json`'s `mcpServers` additively (`aiLib.mergeJsonKey`), because Claude Code writes to that file constantly and a wholesale replace would fight it. Removing a server needs `claude mcp remove <name> -s user` by hand; Nix is authoritative for additions only.

## Maintenance

`home/common/ai/maintenance.nix` installs a launchd agent, `claude-prune-transcripts`, weekly, deleting session transcripts in `~/.claude/projects/` older than 30 days, the directory has no built-in eviction and is the largest thing under `~/.claude/`. `home/common/ai/statusline.nix` seeds `~/.claude/statusline.sh`.

## Fresh machine checklist

After `./nix.sh <config>` on a new machine:

1. Set up git identity, see [secrets.md](secrets.md)
2. Add any needed secrets to `~/.config/fish/secrets.fish`
3. Verify plugins loaded: `claude` → `/plugin` (marketplaces install on first launch)
4. Check custom skills landed: `ls ~/.claude/skills`
5. Prune what Nix cannot reach: `./scripts/claude-cleanup.sh` previews, `./scripts/claude-cleanup.sh --apply` executes. It uninstalls plugins no scope enables (the deployed `settings.json` plus every project `.claude/settings*.json` under `$PROJECT_DIR` and live Orca worktrees), removes marketplaces nothing references, drops registry entries for deleted worktrees and the cache versions only they used, and removes code-review-graph's MCP entry and pipx package. Rerun it whenever worktrees or project plugin sets change.
6. Disable unused claude.ai account connectors in claude.ai's own settings, not reachable from this repo.

See [work-setup.md](work-setup.md) for the complete work machine setup.
