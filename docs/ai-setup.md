# AI Setup

Everything Claude Code reads under `~/.claude/` is generated by this flake. Hand-editing `~/.claude/settings.json` or `~/.claude/rules/workflow.md` is overwritten on the next deploy; change the Nix source instead. opencode (personal machine) shares the same instruction sources, see [opencode-setup.md](opencode-setup.md).

## What is loaded every session

The fixed context every session carries before the first prompt: the rules file, every enabled plugin's skill descriptions, the SessionStart text plugins inject unconditionally, the in-repo local skill descriptions, the in-repo agent descriptions, and every connected MCP server's tool names.

Snapshot measured 2026-09-22 on the work machine, not a live guarantee, re-measure to check the current cost. Before this rebuild: ≈21k tokens total, rules file 4.2k, plugin skill descriptions 10.2k, plugin SessionStart injections (caveman, ponytail, superpowers) 3.1k, local skill descriptions 2.6k, agent descriptions 1.0k, MCP tool names 0.9k. After: ≈7-9k. Of that, the caveman and ponytail SessionStart injections (≈2.3k) are a deliberate keep, not overhead to chase, and ≈0.9k is claude.ai account connector tool names, which only claude.ai's own settings can remove, not this repo.

Standing rule: anything stack- or project-specific belongs in that project's own `CLAUDE.md`/`.claude/`, never here. Every local skill, agent and instruction in this repo is machine-wide by construction and loads in every session regardless of what the session is about, so the bar for adding one here is that it holds on every repo on the machine.

## Instructions

`instructions/delegation.md` (Claude only, capped at 1 KB) states the subagent-first override and the per-turn caps. `instructions/shared.md` (harness-agnostic, capped at 4 KB, also read by opencode's `AGENTS.md`) carries tooling, git, vault, code, destructive-ops, security, writing, evidence-and-scope, decisions, learned rules and model tiers. A role's `home/roles/<role>/ai/instructions.md` is appended last via `home.ai.extraInstructions`. `home/common/ai/instructions/default.nix` concatenates the three into `~/.claude/rules/workflow.md`, loaded in every session. `~/.claude/CLAUDE.md` is rtk's own file, an `@RTK.md` import, not generated by this repo.

## Settings

`home/common/ai/settings.nix` merges its keys into `~/.claude/settings.json` on every deploy via `aiLib.mergeJsonObject`. `model` and `modelSettings` are app-written preferences, set with `/model`, and must never be declared here or added to `dropKeys`: `mergeJsonObject` keeps any undeclared live key, so declaring `model` would fight the in-app picker on every deploy. A declared top-level key replaces the live value; `permissions` and `hooks` merge one level deeper; a live hook event survives only if its name is in `keepHookEvents` (Orca's events); `dropKeys` clears `autoCompactWindow`, the one case where leaving an undeclared live key alone would silently override a value this module documents as intentionally unset. `autoMemoryEnabled = true` is declared and re-applied on every deploy: memory holds session-learned facts, the Obsidian vault stays the durable home for how work happens, read on demand by `vault-search`. `enabledPlugins` is rewritten wholesale from `home.ai.plugins` on every deploy, so dropping a plugin there disables it and adding one through the Claude Code UI does not survive the next deploy.

Env vars:

| Var | Purpose |
|---|---|
| `CLAUDE_VAULT_FOLDERS` | role-scoped vault folders the `vault-lint` agent checks scope coverage against |
| `CLAUDE_CODE_SUBAGENT_MODEL` | default subagent model (`sonnet`) when neither a per-call `model` nor an agent's own `model:` says otherwise |
| `CLAUDE_CODE_GOAL_CHECKIN_MINUTES` | set to 0, so a goal waiting on background tasks never triggers a full-context check-in turn (background work already notifies on completion) |
| `PONYTAIL_SUBAGENT_MATCHER` | narrows ponytail's SubagentStart injection to the agent types that actually write code |
| `CLAUDE_RECON_LIMIT` | distinct inline Read/Grep/Glob targets allowed per main-thread turn before `delegate-nudge.sh` denies a further one |

### Hooks

| Event | Matcher | Script |
|---|---|---|
| PreToolUse | Bash | `block-ai-attribution.sh` |
| PreToolUse | Bash | `destructive-guard.sh` |
| PreToolUse | Bash | `rtk-rewrite.sh` |
| PreToolUse | Read\|Grep\|Glob | `delegate-nudge.sh` |
| PreToolUse | Edit\|Write | `force-delegation.sh` |
| PreToolUse | Agent | `subagent-model-gate.sh` |
| PostToolUse | Edit\|Write | `biome-fix.sh` |

Two of these are hard gates sharing turn-boundary logic in `lib/turn-key.sh` (a non-empty `agent_id` bails out so subagents are never restricted, `prompt_id` is the turn key, counters live in a per-namespace dir with a 2-hour GC), so the two hooks never define "a turn" differently:

- `force-delegation.sh` denies a main-thread Edit/Write past 4 distinct files in a turn; repeat edits to an already-allowed file stay free.
- `delegate-nudge.sh` denies a further distinct inline Read/Grep/Glob target past `CLAUDE_RECON_LIMIT` (default 8); re-reading an already-counted target stays free.

`subagent-model-gate.sh` denies any Agent dispatch that omits `model`, names anything other than `haiku`, `sonnet` or `opus` (or the matching `claude-*` id), or uses `subagent_type: fork`, which always inherits the parent model. The deny text carries the tier table, so the main thread picks a tier by complexity on the retry; `CLAUDE_CODE_SUBAGENT_MODEL` stays as the fallback for agents whose frontmatter pins nothing.

`block-ai-attribution.sh` rejects AI attribution in commits, PRs and reviews. `destructive-guard.sh` turns the irreversible commands `shared.md` names (`git reset --hard`, `git clean`, whole-tree checkout or restore, force push, recursive `rm` outside `/tmp`, `find -delete`, `DROP`/`TRUNCATE`) into a permission prompt, so auto mode still stops for a human yes. `rtk-rewrite.sh` rewrites read-only commands through `rtk` for token-cheap output, a silent no-op when `rtk` is absent. `biome-fix.sh` runs `biome check --write` on just the edited file, a no-op unless the project has a biome config.

## Plugins

Marketplaces and plugins live in `home/common/ai/plugins.nix`: `caveman`, `mattpocock-skills`, `ponytail`, plus the built-in `code-review`, the fixed set on both machines. Third-party marketplaces are pinned to a reviewed commit sha (`@<sha>`); a pin after the last `@` that is not a full 40-char lowercase commit sha fails `nix flake check` outright. `scripts/verify-plugins.sh` is the one check that catches a typo'd plugin name, since a bad name otherwise fails silently: Claude Code installs nothing and logs nothing.

Stack- or project-specific plugins are enabled per project instead of here: `frontend-slides` in the `frontend` repo's own `.claude/settings.json`, and Mindera's `mp-ai-workbench`/`mp-fe-design` (the `ai-workbench` marketplace) in the `frontend`, `workspace` and `ai-workbench` repos' own settings, since project settings take precedence over user settings and a worktree shares the main checkout's file. A project's `enabledPlugins` can also set a global plugin to `false`, turning it off for that project alone; this repo's own `.claude/settings.json` does that for `mattpocock-skills` and carries the permission allow-list for the mandatory checks below.

To find which plugin ships a skill:

```bash
git clone --filter=blob:none --no-checkout --depth 1 https://github.com/<owner>/<repo> /tmp/probe
git -C /tmp/probe show HEAD:.claude-plugin/marketplace.json | jq -r '.plugins[] | "\(.name)\t\(.source)"'
git -C /tmp/probe ls-tree -r --name-only HEAD | grep '<skill-you-want>/SKILL.md'
```

A disabled-but-installed plugin costs nothing: only `enabledPlugins` loads at session start. `claude plugin uninstall` is disk hygiene, not required for the token budget.

## Local skills, agents, workflows

Three skills (`llm-council`, `obsidian-vault`, `unslop`), two agents (`vault-lint`, `vault-search`), one workflow (`llm-council`), declared in `home/common/ai/skills/default.nix`, `agents/default.nix` and `workflows/default.nix`.

`mkLocalSkills` copies, not symlinks, the declared directories into `~/.claude/skills` on every deploy; `customSkillsReconcile` then deletes any directory or symlink there that isn't declared or listed in `home.ai.externallyManagedSkills` (Orca's own `orca-cli`, `orchestration`, `computer-use`, updated by Orca's installer, never this repo). `mkLocalAgents` and `mkLocalWorkflows` install plain `home.file` symlinks instead: an agent or workflow file is read-only input nothing ever writes into, so a store symlink is safe.

Build-time assertions in `lib/ai.nix` fail `nix flake check` when a name in a `names` list has no matching file, or a file on disk under `local/` is missing from its `names` list, the same check that replaced `verify-references.sh`.

Add one:

| Add | Create | Register in |
|-----|--------|-------------|
| Skill | `skills/local/<name>/SKILL.md` | `skills/default.nix` |
| Agent | `agents/local/<name>.md` | `agents/default.nix` |
| Workflow | `workflows/local/<name>.js` | `workflows/default.nix` |

## MCP

No MCP server is shared across every machine. The personal role merges `shadcn` into `~/.claude.json`'s `mcpServers` additively (`aiLib.mergeJsonKey`), because Claude Code writes to that file constantly and a wholesale replace would fight it. Removing a server needs `claude mcp remove <name> -s user` by hand; Nix is authoritative for additions only.

## Maintenance

`home/common/ai/maintenance.nix` installs a launchd agent, `claude-prune-transcripts`, weekly, deleting session transcripts in `~/.claude/projects/` older than 30 days, the directory has no built-in eviction and is the largest thing under `~/.claude/`. `home/common/ai/statusline.nix` seeds `~/.claude/statusline.sh`.

## Fresh machine checklist

After `./nix.sh <config>` on a new machine:

1. Set up git identity, see [secrets.md](secrets.md)
2. Add any needed secrets to `~/.config/fish/secrets.fish`
3. Verify plugins loaded: `claude` → `/plugin` (marketplaces install on first launch)
4. Check custom skills landed: `ls ~/.claude/skills`
5. Clean up leftovers from before the token-budget rebuild:

```bash
claude mcp remove code-review-graph -s user
pipx uninstall code-review-graph
claude plugin uninstall superpowers
claude plugin uninstall figma
claude plugin uninstall claude-code-setup
claude plugin uninstall web-quality-skills
claude plugin uninstall skills@ai-builder-club
claude plugin marketplace remove addy-web-quality-skills
claude plugin marketplace remove ai-builder-club
rm -rf "${TMPDIR:-/tmp}/claude-compacted"
```

6. Disable unused claude.ai account connectors in claude.ai's own settings, not reachable from this repo.

See [work-setup.md](work-setup.md) for the complete work machine setup.
